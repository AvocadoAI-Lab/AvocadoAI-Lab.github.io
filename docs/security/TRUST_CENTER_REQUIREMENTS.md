# Public Trust Center Requirements

The Trust Center should answer enterprise due-diligence questions without overstating certification or control maturity.

## Initial public sections

- Data handling principles.
- AI and customer-data usage boundaries.
- Public-site security and responsible disclosure.
- SenseL deployment options: SaaS, on-premise, and air-gapped where actually supported.
- Identity and access-control approach.
- Encryption approach.
- Audit and evidence approach.
- Data retention and deletion principles.
- Subprocessor disclosure when finalized.
- Availability and support policy when contractually defined.
- Security documentation request process.

## Publication controls

Each statement needs an implementation owner, evidence location, security review date, legal review when required, and an approved public detail level. Do not claim ISO certification, SLA, penetration testing, encryption algorithm, or data residency unless current evidence supports the exact wording.

## Future authenticated Trust Center

Sensitive evidence such as audit reports, detailed architecture, security questionnaires, certificates, and penetration-test summaries should be shared only through an approved gated process under NDA and access logging.
